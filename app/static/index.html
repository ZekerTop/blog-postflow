  1. Set up once
    In Settings, add a GitHub token (fine-grained: Contents read/write + Actions read-only on the target repos), then add your blogs: pick a theme preset and fill in repo, branch and posts folder. Click “Check” to confirm Postflow can write.
    2. 
          
  2. Paste the body
    Paste your post into “Body”, or drag a .md file in. It autosaves as a local draft, so a refresh won't lose it.
    3. 
          
  3. Fill in metadata
    Enter the title yourself (AI never changes it), then click “AI: slug & SEO”. The slug distills the title's topic into English (e.g. python-314-free-threading-template-strings-upgrade), the description is 100–130 characters for search snippets, and keywords cover 15–30 synonyms and long-tail questions. Tags and categories are yours to fill.
    4. 
          
  4. Preview
    See the exact Markdown and file path for each blog. If the file already exists you'll be told, and need to turn on “Overwrite”.
    5. 
          
  5. Publish
    One commit per selected blog; each repo's GitHub Actions builds and deploys. The result card refreshes itself until the deploy finishes.
    6. 
        

        
For a new blog, set the branch to postflow-test first. Once the output looks right, switch back to main. The live site isn't touched.

发布失败：还没配置 GitHub Token
去「设置 → GitHub」填 Token 并保存。Token 只存在服务器本地数据库，页面上只显示末 4 位。

        
GitHub 401 / 403 / 404
401 是 Token 无效或过期；403 是 Token 没有这个仓库的写权限；404 多半是仓库名写错，或 fine-grained Token 没勾选这个仓库。在「设置」里点该博客的「检查连接」可以看到具体原因。

        
三个博客在不同 GitHub 账号，Token 怎么配？
每个博客是独立的仓库，可以属于不同账号。fine-grained Token 只能授权给一个账号下的仓库，所以：多数博客所在账号的 Token 填在「设置 → 密钥」作为全局默认；其他账号下的博客，编辑该博客，在「专用 GitHub Token」里填那个账号的 Token。检查连接、预览、发布、查部署状态都会自动用对应的 Token。

        
从飞书、公众号复制的内容怎么变成 Markdown？
直接复制、粘贴进「正文」就行：标题、加粗、列表、引用、代码块、表格、链接、图片会自动转成 Markdown，转错了按 ⌘Z 撤销；想原样粘贴纯文本按 ⌘⇧V。注意：飞书文档里的图片链接要登录才能看，公众号图片有防盗链，这两种图片发布前要换成图床链接，粘贴时会提醒。

        
以前发的文章怎么改、怎么删？
顶部「文章」页会列出博客仓库里的全部文章。点「编辑」载入到写作页，改完发布会写回原文件，只改你动过的部分，没动的字段（包括自定义字段）原样保留。点「删除」会从仓库删掉这篇，并在同一次提交里登记到放行名单，部署不会被 SEO 守门拦下。已被收录的文章尽量只改不删，删了老链接会 404。

        
提示「目标文件已存在」
同一个 slug 已经发过。确认要更新就打开「目标文件已存在时覆盖」再发；不想覆盖就换一个 slug。

        
已提交，但网站没更新
提交后由各仓库的 GitHub Actions 构建部署，通常 1～3 分钟。结果卡片里点 Actions 链接可以看日志；失败多是 workflow 或部署密钥的问题，不是本服务。

        
生成的 front matter 和我的主题对不上
编辑该博客 → 换一个更接近的主题预设；还有出入就在「高级 → 覆盖预设」里写 YAML，比如 date_format: '%Y-%m-%d'，或用 fields 重新定义字段（取值写 $title、$tags、$cover 等）。改完先预览。

        
AI 用中转站怎么配？
「设置 → AI 接口」：中转站是 Anthropic 格式（如 Claude Code 用的那种）就选「Anthropic 格式」，接口地址填中转站给的地址；是 OpenAI 格式（DeepSeek、Kimi、OpenRouter、各种 API 聚合）就选「OpenAI 兼容格式」，地址一般填到 /v1。填好 Key 和模型名，先点「测试连接」，通过了再保存。

        
AI 生成失败
先去「设置 → AI 接口」点「测试连接」看具体原因：401 是 Key 不对，404 多半是接口地址或模型名不对，429 是额度或限流。AI 只是辅助，失败了手动填写一样能发布。

        
后来新加了博客，旧文章怎么补发？
「历史」里每条记录会出现「补发 N 个」，用当时保存的内容生成并提交。想先改内容，就点「载入编辑」。

        
草稿存在哪？
只存在当前浏览器本地。换设备、清除网站数据都会丢失，重要文章请自己留底。

    
      

      

        
Publish failed: no GitHub token yet
Go to Settings → GitHub, enter a token and save. It's stored only in the server's local database, and the page shows just the last 4 characters.

        
GitHub 401 / 403 / 404
401 means the token is invalid or expired; 403 means it can't write to this repo; 404 usually means a typo in the repo name, or the fine-grained token wasn't granted this repo. Click “Check” on the blog in Settings to see the exact cause.

        
My blogs live under different GitHub accounts. Which token goes where?
Each blog is its own repo and can belong to any account. A fine-grained token only covers one account's repos, so put the token for the account that holds most of your blogs in Settings → GitHub as the default. For a blog under another account, edit it and fill in “Blog-specific GitHub token”. Check, preview, publish and deploy status all use the right token automatically.

        
How does content copied from Feishu or WeChat become Markdown?
Just copy and paste into “Body”: headings, bold, lists, quotes, code blocks, tables, links and images are converted. Press ⌘Z to undo a bad conversion, or ⌘⇧V to paste plain text. Note: Feishu image links need a login and WeChat images block hotlinking, so replace them with hosted image URLs before publishing. You'll get a reminder when you paste.

        
How do I edit or delete a post I published earlier?
The “Posts” page lists every post in the blog repo. “Edit” loads it into the Write page; publishing writes back to the original file and changes only what you edited, keeping every untouched field (custom ones included). “Delete” removes the post from the repo and, in the same commit, adds it to the allowlist so the SEO guard doesn't block the deploy. Prefer editing indexed posts over deleting them: deleted links return 404.

        
“The file already exists”
A post with this slug was published before. To update it, turn on “Overwrite if the file already exists” and publish again; otherwise pick a different slug.

        
Committed, but the site didn't update
Each repo's GitHub Actions builds and deploys after the commit, usually within 1–3 minutes. Follow the Actions link on the result card for logs. Failures there are almost always the workflow or deploy keys, not Postflow.

        
The generated front matter doesn't match my theme
Edit the blog and pick a closer theme preset. If it's still off, write YAML under “Advanced → Preset overrides”, e.g. date_format: '%Y-%m-%d', or redefine fields with fields (values like $title, $tags, $cover). Preview after changing.

        
How do I use an API relay for AI?
Settings → AI provider: for an Anthropic-format relay (like the ones Claude Code uses), choose “Anthropic format” and enter the relay's URL. For an OpenAI-format one (DeepSeek, Kimi, OpenRouter, aggregators), choose “OpenAI-compatible”; the URL usually ends in /v1. Enter the key and model name, click “Test connection”, and save once it passes.

        
AI generation failed
Go to Settings → AI provider and click “Test connection” for the exact cause: 401 is a bad key, 404 is usually a wrong URL or model name, 429 is quota or rate limiting. AI is optional: you can always fill the fields in by hand and publish.

        
I added a blog later. How do I publish old posts to it?
In History, each record shows “Publish to N more”, which regenerates and commits the post as it was saved. To change it first, click “Load to edit”.

        
Where is my draft stored?
Only in this browser. Switching devices or clearing site data loses it, so keep your own copy of anything important.
